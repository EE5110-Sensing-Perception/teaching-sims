By the end of this guide you should be able to:

  • say precisely what a frame is, and distinguish the sensor, body and navigation frames;
  • convert an attitude between the aerospace convention (NED/FRD) and the ROS convention (ENU/FLU);
  • build and read a rotation matrix, ZYX Euler angles, a unit quaternion and an axis–angle vector, and convert between them;
  • explain why the order of rotations matters, and what "intrinsic" and "extrinsic" mean;
  • explain gimbal lock as a failure of the coordinates, not of the vehicle;
  • integrate gyro rates into attitude, and explain first-order, renormalisation and coning errors.

1. Why this matters

Everything an IMU measures is a vector expressed in the sensor's own axes. Before a robot can use that measurement, for example to know which way is down or which way it is heading, it must rotate the vector into a frame that means something to the rest of the system. Getting this wrong is the single most common source of IMU bugs in robotics: an axis swapped, a sign flipped, yaw measured from the wrong reference, a quaternion stored in the wrong order. None of these bugs crash the program. They quietly produce a robot that drives in circles.

This guide builds the vocabulary and the mathematics that every later guide relies on.

3. Background: vectors, frames and notation

3.1 A vector is not its components

A vector such as "gravity" or "the direction the nose points" is a physical arrow. To compute with it we pick a frame and write down its three components along that frame's axes. We use a superscript for the frame the components are written in:

  • \(\mathbf v^n\): the vector \(\mathbf v\) written in navigation axes;
  • \(\mathbf v^b\): the same vector written in body axes.

Both describe the same arrow. The rotation matrix converts one set of numbers into the other:

$$\mathbf v^n = R^n_b\,\mathbf v^b, \qquad \mathbf v^b = R^b_n\,\mathbf v^n = (R^n_b)^\top\mathbf v^n .$$

Read \(R^n_b\) as "from \(b\) to \(n\)". The subscript cancels against the vector's superscript, which is a useful check that you have not used the wrong matrix. Because a rotation matrix is orthogonal, its inverse is simply its transpose.

3.2 Dot and cross products (refresher)

  • Dot product \(\mathbf a\cdot\mathbf b = a_xb_x+a_yb_y+a_zb_z = \|\mathbf a\|\|\mathbf b\|\cos\gamma\). It measures how much two vectors point the same way. For unit vectors it is the cosine of the angle between them.
  • Cross product \(\mathbf a\times\mathbf b\) is perpendicular to both, with length \(\|\mathbf a\|\|\mathbf b\|\sin\gamma\) and direction given by the right-hand rule.

The cross product can be written as a matrix multiplication, which is how it appears in the kinematics:

$$[\mathbf a]_\times = \begin{bmatrix}0&-a_z&a_y\\ a_z&0&-a_x\\ -a_y&a_x&0\end{bmatrix},\qquad [\mathbf a]_\times\,\mathbf b = \mathbf a\times\mathbf b .$$

The matrix is skew-symmetric: \([\mathbf a]_\times^\top = -[\mathbf a]_\times\).

3.3 What makes a matrix a rotation

A rotation preserves lengths and angles, and does not mirror. In matrix terms:

  • Orthogonal: \(R^\top R = I\). The columns are unit length and mutually perpendicular. Lengths and angles are preserved.
  • Proper: \(\det R = +1\). A matrix with \(\det R=-1\) is also orthogonal but it is a reflection, turning a right-handed frame into a left-handed one. No physical motion can do that, so a filter that produces \(\det R=-1\) has a bug.
Key idea. The columns of \(R^n_b\) are the body axes written in navigation coordinates: column 1 is where the nose points, column 2 is the body y axis, column 3 the body z axis. The rows are the navigation axes written in body coordinates. Reading a DCM this way is the fastest route to debugging one.

4. Frames and conventions

4.1 The three frames

A robot needs at least three frames:

  1. Sensor frame \(s\): the chip's axes. You rarely use it directly, because the chip may be mounted rotated on the circuit board.
  2. Body frame \(b\): the robot's axes. The fixed mounting rotation \(R_{bs}\) comes from the CAD model or a calibration, and \(\mathbf f^b = R_{bs}\mathbf f^s\).
  3. Navigation frame \(n\): local-level and Earth-fixed. For a robot operating over a few kilometres we treat it as flat and non-rotating (Guide 8 revisits this).

4.2 Two conventions: aerospace and ROS

Two conventions dominate. They describe the same physics with different axis choices:

Aerospace (and most IMU datasheets, PX4, ArduPilot)ROS REP-103 (and most robotics software)
Navigation frameNED: x = North, y = East, z = DownENU: x = East, y = North, z = Up
Body frameFRD: x = Forward, y = Right, z = DownFLU: x = Forward, y = Left, z = Up
Yaw zero and direction0 = facing North, positive clockwise seen from above0 = facing East, positive counter-clockwise seen from above
Nose-up pitchpositivenegative
Gravity vector\(\mathbf g^n=[0,0,+g]\)\(\mathbf g^n=[0,0,-g]\)

The conversion between the two is a pair of fixed axis permutations:

$$R^{\mathrm{ENU}}_{\mathrm{FLU}} = T\,R^{\mathrm{NED}}_{\mathrm{FRD}}\,T_b,\qquad T=\begin{bmatrix}0&1&0\\1&0&0\\0&0&-1\end{bmatrix},\qquad T_b=\begin{bmatrix}1&0&0\\0&-1&0\\0&0&-1\end{bmatrix}.$$

\(T\) swaps north and east and flips the vertical. \(T_b\) flips body y and z (right becomes left, down becomes up). In Euler angles the result is:

$$\psi_{\mathrm{ROS}} = 90^\circ - \psi_{\mathrm{NED}},\qquad \theta_{\mathrm{ROS}} = -\theta_{\mathrm{NED}},\qquad \phi_{\mathrm{ROS}} = \phi_{\mathrm{NED}} .$$
Common bug. A ROS node reports yaw = 0 and a developer assumes the robot faces north. It faces east. Always check which convention a driver or library uses before combining its output with anything else.

5. Representing attitude

There are four common ways to write down a rotation. Each has a job it does well and a way it fails.

5.1 Elementary rotations

A rotation by angle \(a\) about a single coordinate axis is an elementary rotation:

$$R_x(a)=\begin{bmatrix}1&0&0\\0&\cos a&-\sin a\\0&\sin a&\cos a\end{bmatrix},\quad R_y(a)=\begin{bmatrix}\cos a&0&\sin a\\0&1&0\\-\sin a&0&\cos a\end{bmatrix},\quad R_z(a)=\begin{bmatrix}\cos a&-\sin a&0\\\sin a&\cos a&0\\0&0&1\end{bmatrix}.$$

Each leaves its own axis unchanged (the row and column of ones) and rotates the other two in their plane.

5.2 ZYX Euler angles

The aerospace convention builds the attitude from yaw, then pitch, then roll:

$$R^n_b = R_z(\psi)\,R_y(\theta)\,R_x(\phi).$$

Multiplying it out:

$$R^n_b=\begin{bmatrix} c_\theta c_\psi & s_\phi s_\theta c_\psi - c_\phi s_\psi & c_\phi s_\theta c_\psi + s_\phi s_\psi\\ c_\theta s_\psi & s_\phi s_\theta s_\psi + c_\phi c_\psi & c_\phi s_\theta s_\psi - s_\phi c_\psi\\ -s_\theta & s_\phi c_\theta & c_\phi c_\theta\end{bmatrix}$$

where \(c_\theta=\cos\theta\), \(s_\theta=\sin\theta\), and so on. To recover the angles from a matrix, read off the bottom row and first column:

$$\theta = -\arcsin R_{31},\qquad \phi=\operatorname{atan2}(R_{32},\,R_{33}),\qquad \psi=\operatorname{atan2}(R_{21},\,R_{11}).$$
atan2. \(\operatorname{atan2}(y,x)\) returns the angle of the point \((x,y)\) in the full range \(-180^\circ\) to \(+180^\circ\). Plain \(\arctan(y/x)\) only covers \(\pm 90^\circ\) and cannot tell \((1,1)\) from \((-1,-1)\). Always use atan2 for angles. Note the argument order: \(y\) first.

5.3 Axis–angle and the rotation vector

Euler's rotation theorem says any rotation can be achieved by a single rotation of angle \(\alpha\) about a fixed unit axis \(\hat n\). The corresponding matrix is given by Rodrigues' formula:

$$R = I + \sin\alpha\,[\hat n]_\times + (1-\cos\alpha)\,[\hat n]_\times^2 .$$

For a small angle, \(\sin\alpha\approx\alpha\) and \(1-\cos\alpha\approx 0\), so \(R\approx I+[\alpha\hat n]_\times\). This small-angle form is how filters represent attitude errors.

5.4 Unit quaternions

A quaternion has a scalar part and a vector part. The unit quaternion for a rotation of \(\alpha\) about \(\hat n\) is

$$q = \begin{bmatrix}q_w\\ \mathbf q_v\end{bmatrix} = \begin{bmatrix}\cos(\alpha/2)\\ \hat n\sin(\alpha/2)\end{bmatrix},\qquad \|q\|=1 .$$

Quaternions compose with the quaternion product \(\otimes\):

$$p\otimes q = \begin{bmatrix}p_wq_w - \mathbf p_v\cdot\mathbf q_v\\ p_w\mathbf q_v + q_w\mathbf p_v + \mathbf p_v\times\mathbf q_v\end{bmatrix}.$$

A vector is rotated by \(\mathbf v^n = q\otimes[0,\ \mathbf v^b]\otimes q^{*}\), where \(q^*=[q_w,\,-\mathbf q_v]\) is the conjugate (the inverse for a unit quaternion). In practice most libraries convert \(q\) to a matrix and multiply.

Double cover. Replacing \(\alpha\) by \(\alpha+360^\circ\) gives the same physical rotation but flips the sign of every quaternion component, because of the half angle. So \(q\) and \(-q\) represent the same rotation.

Two practical traps.
  • Sign: averaging \(q\) and \(-q\) gives zero, and differencing them gives a "360° error" for identical attitudes. Before averaging or differencing, flip one quaternion so that \(q_1\cdot q_2\ge 0\).
  • Storage order: this module writes \(q=[w,x,y,z]\) (scalar first, Hamilton convention). ROS messages, Eigen's constructor and SciPy's as_quat() use \([x,y,z,w]\). Check every interface.

6. Composition order: intrinsic and extrinsic

Rotations do not commute: rotating 90° about z and then 90° about y gives a different result from doing it the other way round. So the order of the three Euler rotations must be stated, and so must the axes they are about.

  • Intrinsic rotations are about the body's own, current axes. The aerospace sequence is intrinsic Z–Y′–X″: yaw about body z, then pitch about the new body y (written y′), then roll about the newest body x (x″).
  • Extrinsic rotations are about the fixed navigation axes.

An intrinsic sequence is the same as the extrinsic sequence in the reverse order. Intrinsic Z–Y′–X″ equals extrinsic X–Y–Z about fixed axes, and both give \(R_z(\psi)R_y(\theta)R_x(\phi)\). The rule for the matrix product is:

Rule of thumb. Intrinsic (body-axis) rotations multiply on the right; extrinsic (fixed-axis) rotations multiply on the left. So \(R_z R_y R_x\) is read left to right as intrinsic "yaw, then pitch, then roll", or right to left as extrinsic "roll, then pitch, then yaw about fixed axes".

7. Gimbal lock

The gyro measures body rates \(\boldsymbol\omega=[\omega_x,\omega_y,\omega_z]\). The Euler angles change at rates

$$\begin{bmatrix}\dot\phi\\ \dot\theta\\ \dot\psi\end{bmatrix} = \begin{bmatrix}1 & \sin\phi\tan\theta & \cos\phi\tan\theta\\ 0&\cos\phi&-\sin\phi\\ 0 & \sin\phi/\cos\theta & \cos\phi/\cos\theta\end{bmatrix}\boldsymbol\omega .$$

At \(\theta=\pm 90^\circ\), \(\cos\theta=0\) and the first and last rows blow up. Physically, when the nose points straight up, the yaw axis and the roll axis line up, so yaw and roll describe the same motion. Only their difference (or sum) is defined. This is gimbal lock.

Key idea. Nothing happens to the vehicle at 90° pitch. The coordinates become singular, in the same way that longitude is undefined at the North Pole. This is why filters propagate quaternions or rotation matrices internally, and convert to Euler angles only for display.

8. Attitude kinematics and integration

8.1 The continuous-time equations

If the body rotates with rate \(\boldsymbol\omega\) (in body axes), the attitude changes as

$$\dot R^n_b = R^n_b\,[\boldsymbol\omega]_\times,\qquad \dot q = \tfrac12\,q\otimes\begin{bmatrix}0\\ \boldsymbol\omega\end{bmatrix}.$$

Where does the first come from? Each column of \(R\) is a body axis, and a vector fixed in a body rotating at \(\boldsymbol\omega\) changes at \(\boldsymbol\omega\times\) itself. Written in body axes and rotated to nav, that is \(R[\boldsymbol\omega]_\times\). The factor \(R\) is on the left because \(\boldsymbol\omega\) is in body axes (an intrinsic rotation).

8.2 Discrete-time integration

The IMU delivers samples every \(\Delta t\). Three ways to step the attitude forward:

  1. First-order (Euler) DCM step: \(R_{k+1}=R_k(I+[\boldsymbol\omega]_\times\Delta t)\). Simple, but \(I+[\boldsymbol\omega]_\times\Delta t\) is not a rotation: its determinant is \(1+\|\boldsymbol\omega\|^2\Delta t^2\). Every step stretches the matrix slightly, and the error compounds.
  2. Renormalisation: after each step, force \(R\) back onto SO(3), for example by Gram–Schmidt on its columns or via the SVD. This restores \(R^\top R=I\) and \(\det R=1\), but it does not recover the lost accuracy. The attitude is still wrong; it is just a valid rotation that is wrong.
  3. Exponential-map step: treat the rotation over one step as an axis–angle rotation of \(\boldsymbol\omega\Delta t\) and apply it exactly: $$q_{k+1} = q_k\otimes\begin{bmatrix}\cos(\|\boldsymbol\omega\|\Delta t/2)\\ \hat{\boldsymbol\omega}\,\sin(\|\boldsymbol\omega\|\Delta t/2)\end{bmatrix}.$$ This is exact whenever \(\boldsymbol\omega\) is constant over the step. Renormalise \(q\) occasionally to remove round-off.

8.3 Coning

If the rotation axis itself moves within a sample interval, even the exponential map is wrong, because it assumes a constant \(\boldsymbol\omega\). A classic case is coning: \(\boldsymbol\omega = [a\cos\Omega t,\ a\sin\Omega t,\ 0]\). The x and y rates are sinusoids that average to zero, yet the body undergoes a steady net rotation about z. Sampled rates miss part of it.

Higher-grade IMUs solve this internally: they integrate at kHz rates, apply a coning correction, and output angle increments \(\Delta\boldsymbol\theta\) (and velocity increments \(\Delta\mathbf v\)) per output sample. If your IMU offers these increments, use them rather than instantaneous rates.

9. Worked examples

Example 1.1 — Reading a DCM and rotating a vector

Problem. A ground robot is level with yaw \(\psi=30^\circ\) (NED). A LiDAR on the robot detects an obstacle 2 m straight ahead. Where is the obstacle relative to the robot, in north and east?

Solution.

  1. Level means \(\theta=\phi=0\), so \(R^n_b = R_z(30^\circ)\): $$R^n_b=\begin{bmatrix}0.866&-0.500&0\\0.500&0.866&0\\0&0&1\end{bmatrix}.$$
  2. "Straight ahead" in body axes is \(\mathbf v^b=[2,\,0,\,0]\).
  3. \(\mathbf v^n = R^n_b\mathbf v^b = 2\times(\text{first column}) = [1.732,\ 1.000,\ 0]\).

Answer. 1.73 m north and 1.00 m east. Notice that we did not need the full multiplication: a body x vector just picks out the first column.

Example 1.2 — Euler angles to DCM and back

Problem. Build \(R^n_b\) for \(\psi=30^\circ,\ \theta=20^\circ,\ \phi=10^\circ\), then recover the angles from the matrix.

Solution.

  1. Compute \(R_z(30^\circ)R_y(20^\circ)R_x(10^\circ)\), either directly or from the closed form in §5.2: $$R^n_b=\begin{bmatrix}0.8138&-0.4410&0.3785\\0.4698&0.8826&0.0180\\-0.3420&0.1632&0.9254\end{bmatrix}.$$
  2. Check it is a rotation: each column has unit length, for example \(0.8138^2+0.4698^2+0.3420^2=1.000\).
  3. Pitch: \(\theta=-\arcsin(R_{31})=-\arcsin(-0.3420)=20.0^\circ\).
  4. Roll: \(\phi=\operatorname{atan2}(0.1632,\ 0.9254)=10.0^\circ\).
  5. Yaw: \(\psi=\operatorname{atan2}(0.4698,\ 0.8138)=30.0^\circ\).

Interpretation. Column 1, \([0.814,\,0.470,\,-0.342]\), is the nose direction. Its negative down component (\(-0.342=-\sin 20^\circ\)) shows the nose is pitched up by 20°.

Example 1.3 — Converting NED to ROS

Problem. An autopilot reports yaw 30°, pitch 10° (nose up), roll 5°, in NED/FRD. What does a ROS node expect?

Solution. Apply the rules from §4.2:

  • \(\psi_{\mathrm{ROS}}=90^\circ-30^\circ=60^\circ\) (measured from east, counter-clockwise);
  • \(\theta_{\mathrm{ROS}}=-10^\circ\) (nose up is negative about the left-pointing y axis);
  • \(\phi_{\mathrm{ROS}}=5^\circ\).

Check. Computing \(T\,R^{\mathrm{NED}}_{\mathrm{FRD}}\,T_b\) numerically and extracting ZYX angles gives (60.0°, −10.0°, 5.0°). The pose is the same; only the description changed.

Example 1.4 — A quaternion by hand

Problem. Write the quaternion for a 90° rotation about the z axis, and use it to rotate the vector \([1,0,0]\).

Solution.

  1. \(\alpha=90^\circ\), \(\hat n=[0,0,1]\), so \(q=[\cos 45^\circ,\ 0,\ 0,\ \sin 45^\circ]=[0.7071,\ 0,\ 0,\ 0.7071]\).
  2. Convert to a matrix, or recognise it as \(R_z(90^\circ)\), whose first column is \([0,1,0]\).
  3. So \([1,0,0]\mapsto[0,1,0]\): north becomes east, a 90° clockwise turn seen from above in NED.

Double cover. \(-q=[-0.7071,0,0,-0.7071]\) corresponds to \(\alpha=-270^\circ\) about z, which gives the same rotation matrix. In ROS order, \(q\) would be stored as x=0, y=0, z=0.7071, w=0.7071.

Example 1.5 — Order matters

Problem. Start level, facing north. Sequence A: yaw 90° then pitch 90° (body axes). Sequence B: pitch 90° then yaw 90° (body axes). Where does the nose point after each?

Solution. The nose is the first column of the final matrix.

  • A: \(R_z(90^\circ)R_y(90^\circ)\). The first column is \([0,0,-1]\): the nose points up. Turning east and then pitching up leaves the nose vertical.
  • B: \(R_y(90^\circ)R_z(90^\circ)\). The first column is \([0,1,0]\): the nose points east. After pitching up, "yaw about body z" swings the nose sideways in the vertical plane, bringing it back down to the horizon facing east.

Answer. Same angles, completely different poses.

Example 1.6 — How bad is gimbal lock?

Problem. A quadrotor is at \(\theta=85^\circ\), \(\phi=0\). It rotates 0.5° about its body z axis. How much does the extracted yaw change? Repeat at 89.5°.

Solution. With \(\phi=0\), \(\dot\psi=\omega_z/\cos\theta\), so \(\Delta\psi\approx 0.5^\circ/\cos\theta\).

  • At 85°: \(0.5/\cos 85^\circ = 0.5/0.0872 = 5.7^\circ\).
  • At 89.5°: \(0.5/0.00873=57^\circ\).

Interpretation. A controller or filter written in Euler angles would see enormous, meaningless jumps. The vehicle moved half a degree.

Example 1.7 — First-order integration error

Problem. A gyro reports a constant 90°/s about z, integrated with the first-order DCM step at \(\Delta t=50\) ms. What happens to \(\det R\) after 10 s?

Solution.

  1. Rotation per step: \(\|\boldsymbol\omega\|\Delta t = 1.571\ \text{rad/s}\times0.05\ \text{s} = 0.0785\) rad.
  2. \(\det(I+[\boldsymbol\omega]_\times\Delta t)=1+0.0785^2=1.00617\) per step.
  3. 200 steps: \(1.00617^{200}=3.42\). Each column is stretched by \(\sqrt{3.42}\approx1.85\) in the plane of rotation.

Interpretation. The "rotation" now inflates any vector it touches by 85 %. Renormalising restores unit length, but the heading error accumulated by the first-order steps remains. The exponential map has no such error for a constant rate.

10. Common mistakes

  • Using \(R^n_b\) where \(R^b_n\) is needed. Check that subscripts and superscripts cancel.
  • Mixing conventions: NED yaw fed into an ENU map, or FRD accelerations into a FLU estimator.
  • Quaternion storage order: [w,x,y,z] vs [x,y,z,w].
  • Using atan instead of atan2, which loses the quadrant.
  • Propagating Euler angles in a filter for a vehicle that can pitch steeply.
  • Believing renormalisation fixes integration error.
  • Degrees vs radians: gyros often report deg/s; trigonometric functions expect radians.

12. Practice problems

  1. Write \(R_x(90^\circ)\) and use it to rotate \([0,1,0]\). Describe the result in words.
  2. A DCM has first column \([0,\ -1,\ 0]\) and third column \([0,0,1]\) (NED). Which way does the nose point? What is the yaw?
  3. Show that \([\mathbf a]_\times\mathbf a = \mathbf 0\), and explain what that means physically for \(\dot R=R[\boldsymbol\omega]_\times\).
  4. A ROS node reports yaw 135°. What is the NED yaw, and which compass direction is the robot facing?
  5. Give the quaternion for a 180° rotation about the x axis. Is it different from the quaternion for −180° about x?
  6. Explain why \(\det R=-1\) can never come from integrating a physical rotation rate, but can come from a bad calibration matrix.
  7. A filter's attitude estimate is \(q_1=[0.7071, 0, 0, 0.7071]\) and a reference is \(q_2=[-0.7071, 0, 0, -0.7071]\). What is the true attitude error? What does a naive difference \(q_1-q_2\) suggest?
  8. Integrating at 200 Hz, how large is the per-step rotation for a 500°/s spin? Would a first-order DCM step be acceptable?

14. Answers to practice problems

  1. \(R_x(90^\circ)=\begin{bmatrix}1&0&0\\0&0&-1\\0&1&0\end{bmatrix}\); \([0,1,0]\mapsto[0,0,1]\). In NED: a vector pointing east now points down, as the right wing does after a 90° right roll.
  2. The nose points along \([0,-1,0]\) = west. Yaw \(=\operatorname{atan2}(R_{21},R_{11})=\operatorname{atan2}(-1,0)=-90^\circ\) (equivalently 270°).
  3. \(\mathbf a\times\mathbf a=\mathbf 0\), since a vector is parallel to itself. Rotating about \(\boldsymbol\omega\) leaves the axis \(\boldsymbol\omega\) itself unchanged: the component of any body axis along \(\boldsymbol\omega\) does not change.
  4. \(\psi_N=90^\circ-135^\circ=-45^\circ\), i.e. 315°: the robot faces north-west. (ROS 135° is 135° counter-clockwise from east, which is also north-west.)
  5. \(q=[\cos 90^\circ,\ \sin 90^\circ,0,0]=[0,1,0,0]\). For −180°, \(q=[0,-1,0,0]=-q\): the same rotation, as the double cover requires.
  6. Integration composes small proper rotations, each with determinant +1, and determinants multiply, so the product can never become −1. A calibration matrix is estimated freely; if an axis sign is flipped (for example, the IMU is mounted upside down but the calibration only swaps one axis), the result can be a reflection.
  7. They are the same rotation, so the true error is zero. The naive difference \([1.414, 0, 0, 1.414]\) suggests a huge error. Flip \(q_2\) so that \(q_1\cdot q_2\ge0\) before differencing.
  8. \(500^\circ/\text{s}\times 0.005\ \text{s}=2.5^\circ=0.0436\) rad per step. The first-order determinant growth is \(1.0019\) per step, i.e. about \(e^{0.38}\approx1.46\) after 1 s. Not acceptable; use the exponential map.
